Data Structures and Algorithms · lab 1 · read it after the lab

Same records. Different arrangement. Different amount of work.

A results website holds one record per seat number, and you type 4127. If the records sit in no order, the only safe way to answer is to look at them one by one. If they are sorted, you can open the middle, throw away the half that cannot hold 4127, and repeat. That single difference - how the data is arranged - is what this whole course is about. This guide follows seat number 4127 from the idea to a Python function you write and test yourself.

Read it in order once

Chapters 1-2 are why the course exists. 3 is PyCharm. 4-6 are the only Python you need this week. 7 puts them together into your first algorithm, and 8 is how to start the sheet.

Chapter 1

Same records, different work

After this chapter you can say what a data structure and an algorithm are, and explain why sorting made it safe to ignore half of the records.

1.1Looking for 4127 in an unsorted pile

Six exam records, one per seat number, in no particular order. You have turned over three of them: 2268, 6420 and 3051. None is 4127.

So what can you conclude? Only that 4127 may be one of the other three. To be sure it is not there, you have to look at all six. That is the worst case for an unsorted pile: every record. With a million records, a million looks.

1.2Sorted: one look rules out half

Now the same six records are sorted from smallest to largest, and you look at the fourth. It is 5310.

Read that carefully: if 4127 is here, it is to the left. The order tells you where it would be, not whether it exists. One look ruled out the fourth record and everything after it. Do it again on what is left - look at the middle, drop the half that cannot hold it - and the pile shrinks by half every time.

1.3Counting the looks

Two things this table does not say. First, sorting is work too: somebody has to arrange a million records before anyone can halve them. That work pays off because the same sorted list is searched by many people - every student looking themselves up. For one question, asked once, just scanning is cheaper than sorting first. Second, the third row - a prepared index, like the one at the back of a textbook - is a different idea again, and it comes later in the course.

1.4What this course is

A data structure stores and organises data. An algorithm is the exact steps for a task. We choose them together, to get correct results within our limits of time and memory. Almost every topic this term answers one of five questions:

Where is it?searching · hashing
In what order?sorting
Which comes next?stacks · queues · priority queues
How is it connected?trees · graphs
How much work?counting steps · growth

The lectures decide the order you meet them in. And these are engineering questions, not puzzles:

  • Sensor window. The average of the last 60 readings, every second. Do you add all 60 again each time, or add the new reading and drop the oldest?
  • Packet buffer. Packets arrive faster than a link can send them. Which one leaves next, and what happens when the buffer is full?
  • Event scheduler. A simulator holds thousands of future events. Which one happens next?
  • Route finding. The fastest path across a road map or a network: which point connects to which?

Each is a question plus the operations it needs. That pair is what picks the data structure.

Key idea

The same data, arranged differently, costs a different amount of work to use. You choose the arrangement for the questions you will ask of it, and how often.

بالمصري

نفس البيانات، ترتيب مختلف، شغل مختلف تمامًا. الترتيب هو اللي خلاني أقدر أرمي نص الكروت من غير ما أبص عليهم.

What could fool you
  • "Sorted is always better." Only once the sorting is paid for by many searches. One lookup, then throw the list away: just scan.
  • "It is not in the three I checked, so it is not there." In an unsorted pile you may only say not found after checking every record. Chapter 7 turns this sentence into a line of Python.
  • Halving on an unsorted pile. Looking at the middle of an unsorted pile tells you nothing about either half. The trick needs the order.

Check yourself

Sorted records, smallest to largest. You seek 4127 and inspect a record that holds 5310. What follows?

Chapter 2

AI agents, and how work grows

After this chapter you can explain why a program that passes a small test may still be unfit for the real data, and choose a test that would show it.

2.1What an agent does, and what it leaves to you

Today you can describe a task in plain words and an AI agent writes the program, runs it, and fixes its own errors. That is real, and you will use it. But the requirements have to be stated - the real size of the data, how fast the answer must come, how much memory there is - and the evidence that they are met has to be checked. An agent can help with both; you are the one who has to know what to ask for and what a convincing test looks like.

2.2A duplicate check that compares every pair

Suppose the agent writes a check for duplicate student IDs that compares every pair of IDs once and stops as soon as it finds two the same. With 10 IDs there are 45 pairs; it passes in an instant. The question is what happens at the real size.

2.3Which test would have caught it?

Running the 10-ID test again, or on a faster computer, proves the small case again. A large list where every ID is the same sounds harsh, but the first two IDs already match and the check stops after one comparison. The test that shows the slow case is a large list where every ID is different: no early stop, every pair compared. That is the worst case - and real data can hit it.

A different duplicate check exists that trades some memory for far fewer comparisons, and it is part of this course. The point for now is narrower: you can only judge what you can count.

Key idea

Data structures and algorithms are how you describe a requirement, compare what an agent suggests, and test whether it holds at the real size of the data.

بالمصري

الـAI بيكتب كود بسرعة، بس الكود اللي عدّى اختبار صغير ممكن يقع مع الداتا الحقيقية. مين هيعرف؟ اللي فاهم المادة دي.

What could fool you
  • "It passed the test." Which test? A small one proves the small case.
  • "Computers are fast." A faster computer can cut the time; it does not change how many comparisons this check makes, or how that number grows.
  • "Correct means good enough." A correct program that needs billions of comparisons may still miss the deadline it was written for.

Check yourself

The duplicate check compares every pair and stops at the first duplicate. Which test best shows whether it is too slow for 100,000 students?

Chapter 4

Lists and indexes

After this chapter you can create and print a list, read any value out of it by its index, say what len gives, and predict when Python stops with an IndexError.

4.1The same cards, now in Python

A class register or a results sheet is already a familiar list. In the opening activity you searched seat-number cards by hand. Here we write three of those numbers as a Python list, keeping them together in order.

If this is your first Python session, the notation will be new. Today you will create a list, print it and read a value from it. You do not need to know how it is stored in memory yet. How data structures work inside is part of this course later.

In q00_hello.py, replace the hello line with these two lines. The square brackets [] group the values; commas separate them. The = gives this list the name seats. On the next line, print(seats) uses that name, without quotes.

Before running: do you expect one seat number or all three? Make your prediction, then press Ctrl+Shift+F10. Compare your Run window with this output:

run · Python 3.14
[4127, 3051, 5310]

Change 5310 to 6000 in the first line. Predict what will change, then run again. You should see [4127, 3051, 6000]. Restore 5310 and run once more. You have now used a list. Next, we will read just one value from it.

أول مرة تكتب Python؟ طبيعي إن شكل السطر يبقى جديد. دي أرقام الجلوس اللي اشتغلنا بيها، جمعناها تحت اسم واحد. هنكتبها ونطبعها، وبعدها نقرا رقم منها. إزاي الـ data structures بتشتغل من جوّه، هنتعلّمه بعدين في المادة.

4.2Read one value by its index

We have printed the whole list. An index tells Python which position to read when we want just one value.

run · Python 3.14
3051
3

seats[1] is 3051, not 4127 - index 1 is the second position, because the first is 0. And len(seats) is 3: how many values, which is one more than the last index.

4.3Past the end

Three values means indexes 0, 1 and 2. Ask for seats[3] and Python does not guess or print nothing - it stops:

run · Python 3.14
Traceback (most recent call last):
  File "...\q00_hello.py", line 2, in <module>
    print(seats[3])
          ~~~~~^^^
IndexError: list index out of range
Key idea

An index is a position, counted from 0. Counting from the front, the indexes of a list that is not empty run from 0 to len - 1.

بالمصري

الـindex هو مكان الرقم، مش الرقم نفسه. والعد بيبدأ من صفر، فآخر مكان هو len - 1.

What could fool you
  • Counting from 1. The first value is seats[0]. Everyone gets this wrong at first; say "index zero" out loud until it sticks.
  • Index versus value. In seats[1] the 1 is where to look. What comes back is what sits there.
  • seats[-1] is not an error. A negative index counts from the end, so it is the last value, 5310. Remember that in chapter 7, where -1 means something else.

Check yourself

seats = [4127, 3051, 5310]. What does print(seats[1]) show?

Chapter 5

Loops and counting

After this chapter you can visit every position of a list with for i in range(len(...)), run a line only when an if is true, and keep a count across the loop.

5.1Every index, in order

range(len(seats)) produces exactly the indexes that exist: for three values, 0, 1 and 2. A for hands them to i one at a time and runs the indented lines once for each.

Three rules if you remember some C++, and simply rules if you do not:

  • = stores a value; == asks are these equal?
  • The indented lines belong to the for (or the if). No braces; the colon : opens the block, and four spaces mark what is inside it.
  • range(3) is 0, 1, 2 - the end is not included.

5.2Counting with a loop and an if

How many students got a 7? Visit every position; when the value is 7, add one to a counter. The counter starts at 0 before the loop, so it is set once and then grows.

run · Python 3.14
2

The loop runs three times, but count goes up only twice: at index 0 and index 2. Not 3 (every trip round the loop), not 14 (adding the sevens up), not 1 (nothing stops the loop early). Sheet 1 Q7 asks you to turn this into a function that returns the count.

Key idea

Visit every index with for i in range(len(values)); decide with if; remember across the loop with a variable set before it.

بالمصري

كل لفة في الـfor بتدي i القيمة اللي بعدها، والسطور المزقوقة لجوه بتتنفذ مرة في كل لفة. العداد بيبدأ بره اللوب.

What could fool you
  • count = 0 inside the loop. Then it is reset on every trip, and the answer is at most 1.
  • if grades[i] = 7: with one = is a SyntaxError, and Python 3.14 even asks: Maybe you meant '==' instead of '='?
  • Mixed indentation. Use the Tab key in PyCharm - it inserts four spaces - and never mix in spaces by hand.

Check yourself

With grades = [7, 10, 7, 9, 7, 4], the same loop counting sevens prints what?

Chapter 6

Functions and return

After this chapter you can write a function that takes inputs and hands back a result, and say the difference between return and print.

6.1A named recipe

def gives a recipe a name and lists its inputs in brackets. Nothing inside it runs until somebody calls it. return hands a value back to the line that called, and ends the function at once.

run · Python 3.14
5

The function itself prints nothing. It hands 5 back; the calling line stores it in answer; the last line prints it. Python needs no int in front of the name, as C++ would - it does not require you to declare types.

6.2Why return matters for searching

Because return ends the function immediately, a function can stop searching as soon as it has its answer. That is the whole trick of chapter 7.

Key idea

return hands a value back and stops the function. print only shows something on the screen; the program cannot use what was printed.

What could fool you
  • Printing instead of returning. A function that prints its answer shows it once; one that returns it lets the rest of the program use it.
  • A function that reaches its end without a return hands back None. You will meet that in sheet 1 Q9.
  • Lines after a return in the same block never run.

Check yourself

What does this print? def double(x): return x * 2 then print(double(double(3)))

Chapter 7

Linear search: your first algorithm

After this chapter you can plan, write and test find_index, and explain why return -1 belongs after the loop.

7.1Plan before you type

The task: give back the position of target in the list seats, or -1 if it is not there. Before any code, five lines - the same five you can use whenever you cannot see how to start.

HAVEa list seats - unsorted, may be empty, may repeat - and a target WANTthe index of the first match; -1 if it is not there; the list unchanged TRY[4127, 3051, 5310], target 3051: 4127? no. 3051? yes → 1 STEPSvisit each index left to right; on a match, return that index; only after the loop, return -1 CHECKfirst, middle, last, absent, empty list, repeated target

TRY is the line people skip, and it is the one that writes the rest. Do it with your hands on paper, then describe what your hands did: that description is STEPS.

7.2The code, with each part named

The plan goes into the file as comments, above the code. Each group of lines then gets a comment naming what it is for.

run · Python 3.14
2
-1

Look at the two return lines. return i is inside the if, inside the loop: it runs the moment a match is found, and the function stops. return -1 is at the level of the for, after it: Python reaches it only once the loop has run out of indexes - once every position has been checked. -1 is just this function's signal for not found; it is never a real position here, because indexes start at 0.

7.3Watch it run

Found: three checks, it returns 2, and 2268 and 4890 are never looked at. Not found: five checks - every record - and only then return -1. That is the worst case from chapter 1, now in your own code.

7.4The bug a small test misses

Here is a version an AI agent could easily offer. It runs without an error.

run · Python 3.14
0
-1

At i = 0, if the first record is not the target, the else returns -1 - after one check. So it passes a test for the first seat number, and a test for a seat number that is not there at all. It fails whenever the target is present but not first - and on an empty list it returns neither an index nor -1. It says not found before checking every position, which is exactly the sentence chapter 1 warned about. That is why a handful of tests can miss it. Sheet 1 Q9 asks you to take it apart.

Key idea

Searching an unsorted list left to right, you can only say "not found" after checking every position. So return -1 goes after the loop, not inside it.

بالمصري

في ليستة مش مترتبة، مقدرش أقول "مش موجود" غير لما أشوف كل الأماكن. علشان كده return -1 بره اللوب، و return i جوه الـif.

What could fool you
  • Testing only one case. Test the first, middle and last positions, an absent target, an empty list and a repeated target. Each one catches a different mistake.
  • Using the result as an index without checking. seats[find_index(seats, 9999)] is seats[-1], the last value - no error, just a wrong answer. Check for -1 first.
  • Returning seats[i] instead of i. The task wants the position, not the value you already had.

Check yourself

For find_index([3051, 4127, 3051], 3051), what comes back?
