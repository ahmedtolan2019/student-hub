Chapter 1

Getting something to run

After this chapter you can turn a file of text into a running program, on your own machine and on the lab machines, and you can tell a compile failure apart from a wrong answer.

1.1Six lines, and a job for each one

This is the whole of Example 1 from the lecture. Nothing in it is decoration: take any line away and either the program stops compiling or it stops doing anything.

output
Welcome to C++!
  1. 1#include <iostream> pastes the input/output library into your file before compiling. cout and endl are defined in there. Without this line the compiler has never heard of either name.
  2. 2using namespace std; lets you write cout instead of std::cout. The library keeps its names in a namespace called std so they cannot collide with yours; this line says "look in there too".
  3. 4int main() is where execution starts. Every C++ program has exactly one. The int says main hands a whole number back when it finishes.
  4. 5The braces { and } mark the beginning and end of main's body. Everything between them runs in order, top to bottom.
  5. 6A line comment. Everything after // is for humans; the compiler skips it. For several lines, wrap them in /* and */.
  6. 7The one line that does something. Note the semicolon: it ends the statement. Most first-week compile errors are a missing one.
  7. 9return 0; hands 0 back to whoever started the program, which by convention means "finished, nothing went wrong".
Key idea

Lines 1, 2, 4, 5 and 9 are scaffolding you will type a hundred times this term. Line 7 is the program. When you read someone else's code, find the lines that are not scaffolding first.

1.2Compiling and running are two separate things

Your .cpp file is text. The processor cannot run text. A compiler reads the whole file and produces a second file, the program, which the processor can run. Two steps, two kinds of failure.

A compile error means no program was produced, so there is nothing to run. The message names a file and a line number: go there first, then look at the line above it, because a missing semicolon is usually reported on the following line. A wrong answer means compiling worked perfectly and your instructions were faithfully carried out - they were just not the instructions you wanted. Chapters 3 to 6 are entirely about the second kind.

1.3Two compilers, one language

The lab machines run Dev-C++ on Windows. This guide was written and checked on a Mac using VS Code with Apple's clang++. Every program here compiles unchanged on both, because nothing in Sheet 1 goes near the parts of C++ where compilers differ. What differs is only the two clicks that get you from file to output.

In the lab · Dev-C++

File, then F11

File → New → Source File, type the program, save it as something ending in .cpp, then press F11 to compile and run in one go. F9 compiles without running.

If the black window appears and vanishes instantly, the program finished before you could read it. Dev-C++ usually holds it open with Press any key to continue; if yours does not, add system("pause"); just before return 0; and #include <cstdlib> at the top.

On a Mac · VS Code

Open the file, then Cmd+Shift+B

Open the course folder in VS Code, click into any .cpp file, and press ⌘⇧B. The task compiles the file you are looking at and runs it in the terminal panel underneath.

The output appears under a line reading ----- output -----. Anything printed above that line is the compiler talking to you, not your program.

What could fool you
  • Smart quotes. If you draft your code in Word or paste it from a PDF, " often arrives as “ and ”. The compiler does not recognise those. Type your quotes in the editor.
  • The file extension. Saving as hello.txt or hello gets you a file nothing will compile. It must end in .cpp.
  • A missing semicolon is usually reported on the line after the one you need to fix, because that is where the compiler finally gave up.
  • Reading the last error first. One mistake often produces a cascade. Fix the topmost message, recompile, and watch most of the rest disappear.
  • Editing while the old program runs. Fixing the file does not change the program you already built. Compile again, every time.

Chapter 2

cout sends items, one after another

After this chapter you can look at a cout statement and say exactly what appears on the console, including every space and every line break, before you run it.

2.1Each << hands over one more item

Read cout << a << b << c; as a conveyor belt running left to right. The console has a cursor; each item is written starting wherever the previous item stopped. Nothing is inserted between items - not a space, not a line break. If you want a gap, you have to send one.

That is the entire behaviour, and it explains every layout surprise in Sheet 1. Step through the stall's output line below and watch the cursor move.

Key idea

An item in quotes is printed character for character. An item not in quotes is worked out first, and its answer is printed. Everything in chapters 3 to 6 is about that second kind.

2.2Spaces inside quotes are data (Q3)

Question 3 asks for two triangles side by side. There is no drawing instruction in C++ and none is needed: each line of the picture is one string, and the spaces inside it are as real as the asterisks. Every line below is exactly 20 characters wide - nine for the left triangle, two for the gap, nine for the right one.

2.3Characters you cannot type directly

A double quote would end the string early, and there is no key for "move to the next column". C++ writes these as a backslash plus a letter. The pair counts as one character.

You typeWhat lands on the consoleWhere Sheet 1 needs it
\nEnd this line, start a new oneAn alternative to endl anywhere
\tJump to the next tab stopQ4, to line the table columns up
\"A double quoteWhenever you quote something
\\One backslashPrinting a Windows file path

\t is not "a few spaces". It moves the cursor to the next tab stop, and the console decides where those are, usually every 8 columns. That is why Q4's table lines up without you counting anything, and also why it can look wrong if one entry is long enough to overshoot a stop.

output
P       P*5     P*10
5       25      50
10      50      100
25      125     250
50      250     500
Checked against the lecture

The reference solution for Q4 heads these columns p^2 and p^3, but the numbers underneath are P×5 and P×10: the second row is 10, 50, 100, and 103 is 1000, not 100. The sheet asks for P, P*5, P*10, and that is what the file above prints. Your tutor knows about this one.

What could fool you
  • Expecting a space between items. cout << "a" << "b"; prints ab. There is no separator.
  • Expecting a new line at the end. Without endl or \n the next program output continues on the same line, and in some terminals your last line is not shown at all until something else prints.
  • Counting \t as a fixed number of spaces. It is one character that jumps to a column, so the same \t can produce seven spaces on one row and two on the next.
  • Trailing spaces looking harmless. In Q3 the spaces after the final asterisk are what keep all five strings the same length. An editor set to trim trailing whitespace on save will quietly eat them.
  • Using \ instead of / in a division. They are different characters; only / divides.

Chapter 3

Let the program do the sums

After this chapter you can hand an arithmetic expression to cout and say, in order, which operation it performs first, second and last.

3.1One pair of quotes changes everything

These two lines differ by two characters, and they do entirely different jobs. The first sends eleven characters to the console. The second performs a multiplication and an addition and sends the one number that comes back.

output
10.5 + 2 * 3
16.5
Key idea

Working the answer out on your calculator and typing cout << "16.5"; is not a program. It is a picture of an answer. Give C++ the question and it stays correct when the numbers change.

3.2Order of operations, and why Q5 needs its brackets

C++ follows the ordinary rules: * and / before + and -, left to right among equals, and anything in brackets first. Question 5 asks for a fraction, and a fraction is really a pair of brackets: everything on top is worked out, everything underneath is worked out, and only then does the division happen.

Step through it below. Each click performs exactly one operation, innermost brackets first.

3.3There is no power operator

Questions 8 and 9 both need a side squared. C++ has no ^ for powers - the character exists but means something unrelated to arithmetic, so 9.2^2 will not even compile here. For a square, multiply the number by itself.

output
Area      = 36.6491
Perimeter = 27.6
  1. 1The brackets around 9.2*9.2 are not strictly required, since * and / run left to right anyway. They are there so a reader can see the squared side at a glance. Write brackets for the reader, not only for the compiler.
  2. 2Dividing by 4 is safe here even though 4 is a whole number, because 1.732 * 84.64 is already a decimal. Chapter 4 is about the case where it is not.
What could fool you
  • a/b*c is not a/(b*c). Same precedence means strictly left to right, so it is (a/b)*c. Sheet 1 does not punish this, but Sheet 2 will.
  • Typing the answer instead of the question. cout << 12.1978; scores nothing for Q5. The marker is looking for the expression.
  • Leaving out the multiply sign. 2(3+1) is mathematics, not C++. You must write 2*(3+1).
  • Unbalanced brackets. Count the opening and closing ones. The compiler's message for this is usually unhelpful and points at the wrong line.

Chapter 4

The 1311 grams: int and double

After this chapter you can look at any division in a program and say whether C++ will do real arithmetic or throw the fraction away, before you run it.

4.1The stall, written the obvious way

Question 10: a stall sells 600 kg in 15 hours, 30 minutes and 30 seconds; print the average sale in grams per hour. Two conversions, both of them things you would do without thinking on paper. 600 kg is 600000 g. 30 minutes is 30/60 of an hour and 30 seconds is 30/3600 of an hour. Written straight out:

output
average = 40000 grams/hr

On paper the answer is 38688.9. The program says 40000, it compiled without a single warning, and it will say 40000 every time you run it on every machine in the lab. Before reading on, decide where you think the 1311 grams went.

4.230/60 is zero

C++ picks the kind of arithmetic from the operands, not from what you are trying to achieve. 30 and 60 are both whole numbers - the type is called int - so the division is a whole-number division, and a whole-number division produces a whole number. 30 divided by 60 is 0 remainder 30, so the answer is 0. The remainder is not rounded. It is discarded.

The same happens to 30/3600. The denominator the program actually used was 15 + 0 + 0, a flat 15 hours, and 600000 divided by 15 really is exactly 40000. The program was right about the question it was given.

Key idea

If both sides of a / are whole numbers, C++ does whole-number division and throws the remainder away. If either side has a decimal point, it does real division. The fix is to give one side a decimal point: 30.0/60.

4.4The same bug, wearing a different hat (Q7)

Question 7 approximates π with an alternating series and then asks you to discuss why writing 1 instead of 1.0 changes the result. It is the stall's bug again. In 1/3, both operands are whole numbers, so the term is 0. Every term after the first collapses, the bracket is left holding a bare 1, and the program confidently prints 4.

output
Pi (using 1.0, with decimal point)    = 3.01707
Pi (using 1, without decimal point)   = 4
Checked by compiling both

The sheet's formula has eight terms, ending at -1/15, and gives 3.01707. The lecture screenshot stops at +1/13, seven terms, and gives 3.28374. Neither is a mistake in the other's arithmetic: π is 3.14159, the seventh partial sum sits 0.1421 above it and the eighth sits 0.1245 below. Both files are in the course folder, and both were compiled to produce these numbers.

What could fool you
  • Assuming the compiler will warn you. It will not. 30/60 is a perfectly legal, extremely common thing to write, and -Wall -Wextra says nothing about it.
  • Thinking it rounds. 9/2 is 4, not 5, and 1/3 is 0, not 0.333. The fraction is dropped, always toward zero.
  • Fixing only the first term. In 1.0 - 1/3 the subtraction is real, but 1/3 was already 0 before the subtraction ever happened. Each division is judged on its own two operands.
  • Trusting a suspiciously round answer. 40000 and 4 are both exactly the shape that integer division produces. A number that lands on a round figure when you expected a messy one deserves thirty seconds of suspicion.
  • Writing 30/60.0 versus 30.0/60. Both work. Only one operand needs the decimal point, and which one does not matter.

Chapter 5

Naming the parts

After this chapter you can turn a one-line expression into a program whose quantities have names and units, and you can say what the declared type promises about each one.

5.1Declare, assign, use

The stall's answer does not change when you give its parts names. What changes is that the units become visible, each number has one place to be edited, and the line that does the arithmetic finally reads like the sentence in the question.

  1. 1A declaration. It names three quantities and promises each will hold a number that may have a decimal part. Nothing has a value yet. Three names share one double here, separated by commas, which is what the lecture's solutions do.
  2. 3An assignment. The = is not an equation, it is an instruction: work out the right-hand side and put the result into sales. 600e3 means 600×103, so 600000 - a convenient way to write the kilogram-to-gram conversion without counting zeros.
  3. 4The conversion from chapter 4, now with a unit written beside it. Both .0s are load-bearing.
  4. 5A name can be used on the right of = as soon as it has a value. Here sales and Time both do, so average gets 38688.9.
  5. 7average is not in quotes, so cout prints its value. Put it in quotes and the console would read average = average grams/hr.

5.2The type is a promise about what fits

int holds whole numbers only. double holds numbers with a decimal part. Choosing int for something that has a fraction does not produce an error, a warning, or a rounded value - it produces a silently truncated one, in exactly the way chapter 4 described. And it can bite in two different places. Switch the declaration below and watch the answer, not the code.

Key idea

For every quantity in this course, ask one question: can it have a fraction? If yes, it is a double. Money, times, rates, averages, measurements and populations-that-grow-by-156.042-per-hour are all yes.

5.3Q11 is Q10 with two numbers changed

This is the payoff for naming things. Question 11 asks for 55.53 kg in 2 hours 9 minutes 30 seconds, in kilograms per hour. The structure is identical, and because the answer is wanted in kilograms this time, the mass needs no conversion at all.

output
average = 25.7282 kg/hr
What could fool you
  • Reading = as equals. average = sales / Time; is an instruction, not a statement of fact. Writing sales / Time = average; is not C++.
  • Time and time are different names. C++ is case sensitive throughout. The lecture's solutions use a capital T, so this guide does too; pick one and be consistent.
  • Using a variable before assigning one. Declaring double x; and printing x gives whatever rubbish was in that memory. It may look like 0 on one run and not on the next.
  • Declaring inside the wrong braces. A name declared inside { } stops existing at the closing brace.
  • Forgetting the units. Q10 wants grams per hour from a mass in kilograms; Q11 wants kilograms per hour from a mass in kilograms. The programs differ by a factor of 1000 and neither compiler will mention it.

Check yourself

A classmate declares int Time; and assigns Time = 15 + 30.0/60 + 30.0/3600;. What does the program print for the average?

Chapter 6

How many digits does cout show?

After this chapter you can make a number print in the form the question asks for, and you can explain why that never changes the value the program is holding.

6.1Six significant digits, then a decision

You never asked for 38688.9 to have one decimal place. That is cout's default: show six significant digits - six digits counted from the first non-zero one, wherever the decimal point happens to fall. 38688.876947 has five digits before the point, so one is left for after it.

When six significant digits cannot describe the size of the number, cout switches to scientific notation rather than print something misleading. Question 12 walks straight into this.

output
1.18059e+08

That is 1.18059 × 108, and it is not wrong - it is 118058996 rounded to six significant digits, which is all cout was asked for. It is simply useless as a population figure. Question 12 wants whole people.

6.2Two switches, both from <iomanip>

fixed says "never use scientific notation". setprecision(n) sets the number of digits - and what it counts depends on whether fixed is in effect. That single fact causes most of the confusion around these two.

Both live in a second library, so a program that formats output needs two include lines. Move the dial below and read the sentence underneath it.

Key idea

With fixed, setprecision(n) means n digits after the decimal point. Without it, setprecision(n) means n significant digits in total. Same call, different meaning, which is why Q12 uses both together.

6.3Question 12, assembled

Births minus deaths gives 156.042 people per hour. Multiply by 24 and by 365 and a year adds 1366927.92 people. The population is a double because that yearly figure has a fraction in it, and truncating it to a whole number each year would lose people compounding over five years. It is printed as a whole number because half a person is not a sensible thing to report.

output
At the end of 2025 = 118058996
At the end of 2026 = 119425924
At the end of 2027 = 120792852
At the end of 2028 = 122159780
At the end of 2029 = 123526708
At the end of 2030 = 124893636
Checked by compiling it

The figure for 2026 is 119425923.92 before printing. fixed with setprecision(0) rounds that to 119425924 on the way to the console, while the value inside the program keeps its .92 and carries it into the next year's arithmetic. What could fool you
  • They are sticky. fixed and setprecision stay in force for everything printed afterwards, not just the next item. Set them once, near the top, and remember you did.
  • Printing is not storing. setprecision(0) does not round the variable. Print a value, then use it in a later calculation, and the calculation uses the full value - as Q12's compounding relies on.
  • Forgetting the second include. setprecision without #include <iomanip> fails to compile. fixed happens to be available through <iostream>, so a program can compile with fixed alone and then break the moment you add precision.
  • Reading e+08 as an error. It is a correct number in scientific notation. The program is fine; only the presentation needs fixing.
  • Assuming six digits is a lot. For a population of 118 million it is not even enough to reach the thousands column.

Check yourself
