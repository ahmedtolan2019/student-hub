المقارنة مع الملف المرفق

الكود المرفق بيستخدم int، فبيقرأ أعداد صحيحة بس. نسخة الشرح بتستخدم float لأن نص السؤال بيقول numbers، وده يسمح بقيم زي 2.5.

# Sheet (4), Q #01
# Learning version: accepts decimal input too.
total = 0.0
i = 0
while i < 10:
    num = float(input("Enter number: "))
    total = total + num
    i = i + 1

average = total / 10
print("Average =", format(average, ".3f"))

المقارنة مع الملف المرفق

نسخة الشرح بتضيف رفض الإدخال السالب. الكود المرفق بيفترض إن الطالب ملتزم بشرط non-negative الموجود في السؤال.

# Sheet (4), Q #02
n = int(input("Enter a non-negative integer: "))
if n < 0:
    print("Enter a non-negative integer.")
else:
    fact = 1
    i = 1
    while i <= n:
        fact = fact * i
        i = i + 1
    print("Factorial =", fact)
  • if بيمنع حساب مضروب لعدد خارج المجال المطلوب.
  • fact محتفظ بحاصل ضرب كل الأعداد اللي عدّينا عليها.
  • الطباعة جوه else، لكنها برّه while.
إجابة سؤال التوقع

عشان العامل الأخير n نفسه يدخل في حاصل الضرب.

خد بالك: n! مش n**n. المضروب ضرب الأعداد من 1 لحد n، والأس تكرار ضرب نفس العدد.

المقارنة مع الملف المرفق

الكود المرفق بيبدأ num=1 ويقرأ جوه الحلقة، وبيضيف صفر لمجموع السالب وقت الخروج من غير ما يغيّره. هنا استخدمنا قراءة أولية، وfloat للسماح بالأعداد غير الصحيحة.

# Sheet (4), Q #03
sum_p = 0.0
sum_n = 0.0
num = float(input("Enter a number, 0 to stop: "))
while num != 0:
    if num > 0:
        sum_p = sum_p + num
    else:
        sum_n = sum_n + num
    num = float(input("Enter a number, 0 to stop: "))

print("Sum of positive numbers =", sum_p)
print("Sum of negative numbers =", sum_n)
  • القراءة اللي قبل while بتجهّز أول اختبار.
  • if جوه while، فالتصنيف بيتكرر مع كل عدد.
  • القراءة الأخيرة جوه while لكن برّه if وelse؛ لازم تحصل في الحالتين.

المقارنة مع الملف المرفق

الكود المرفق بيطلب lower ثم upper. أضفنا تبديلًا بسيطًا لو المستخدم دخل الحدين بالعكس. الزوجي والفردي هنا للأعداد الصحيحة.

# Sheet (4), Q #04
start = int(input("Enter the first bound: "))
end = int(input("Enter the second bound: "))
if start > end:
    temp = start
    start = end
    end = temp

even_sum = 0
odd_sum = 0
current = start
while current <= end:
    if current % 2 == 0:
        even_sum += current
    else:
        odd_sum += current
    current += 1

print("Even sum =", even_sum)
print("Odd sum =", odd_sum)
  • temp بيحفظ القيمة الأولى لحد ما التبديل يخلص.
  • += اختصار للجمع ثم الإسناد لنفس المتغير.
  • الصفر زوجي؛ إضافته لا تغيّر المجموع.
إجابة سؤال التوقع

لأ. كده الحد الأخير مش هيتحسب. نستخدم <=.

خد بالك: current += 1 لازم يكون برّه if وelse وجوه while، عشان يحصل مع الزوجي والفردي.

المقارنة مع الملف المرفق

السؤال بيكتب 30000 ثم 30.000. استخدمنا 30000 كما في أول سطر وكود الدكتور. ده توضيح للكتابة، مش حد مختلف.

# Sheet (4), Q #05
n = 0
while 2 ** (n + 1) < 30000:
    n += 1

print("Largest n =", n)
print("2**n =", 2 ** n)
print("2**(n+1) =", 2 ** (n + 1))
  • n=0 بداية صالحة لأن 2**0 أقل من الحد.
  • كل دورة ناجحة بتضيف 1 للأس.
  • طباعة القوة التالية بتوضح سبب التوقف.
إجابة سؤال التوقع

خد بالك: رمز الأس في Python هو **. الرمز ^ مش عملية الأس.

تدريب: استبدل الحد بـ20، وحدد آخر قيمة صالحة وأول قيمة مرفوضة.

المقارنة مع الملف المرفق

الكود المرفق ما بيعالجش السالب، وده ممكن يخلي الحلقة تستمر عند -1. نسخة الشرح بتستخدم abs قبل الحلقة.

# Sheet (4), Q #06
num = abs(int(input("Enter an integer: ")))
total = 0
while num != 0:
    digit = num % 10
    total = total + digit
    num = num // 10

print("Sum of digits =", total)
  • abs بتحوّل السالب لقيمته المطلقة.
  • % 10 بيستخرج آخر رقم من num غير السالب.
  • // 10 بتقلل العدد المتبقي لحد صفر.
إجابة سؤال التوقع

فرق أساسي: الملف المرفق بيستخدم i/fact وwhile i < num. نص الشيت يحتاج 1/fact والوصول إلى n نفسه. نسخة الشرح تطبق الصيغة المطبوعة، والتعديل معلن هنا.

# Sheet (4), Q #09
# Learning version follows the printed series.
n = int(input("Enter a positive integer n: "))
if n < 1:
    print("n must be positive.")
else:
    total = 0.0
    fact = 1
    i = 1
    while i <= n:
        fact = fact * i
        total = total + 1 / fact
        i += 1

المقارنة مع الملف المرفق

التنظيم مطابق لفكرة كود الدكتور. الأعداد المعروضة هنا تصف حدود الحلقات، وليست سجل تشغيل عددي لجدول π.

# Sheet (4), Q #11
import math
print(f"{'n':>4} {'pi':>10}")
for n in range(100, 601, 100):
    total = 0.0
    for j in range(1, n + 1):
        total = total + 1.0 / (j * j)
    pi_approx = math.sqrt(6.0 * total)
    print(f"{n:>4} {pi_approx:>10.6f}")
  • 601 تسمح بوصول n إلى 600.

المقارنة مع الملف المرفق

في الملف المرفق، اختبار k==0 خارج else، فـ0 و1 ممكن يطلع لهم حكمان متناقضان، والسالب ممكن يتصنف أولي. هنا الحكم النهائي جوه فرع num>=2.

# Sheet (4), Q #13
num = int(input("Enter an integer: "))
if num < 2:
    print("Not a prime number")
else:
    count = 0
    i = 2
    while i < num:
        if num % i == 0:
            count += 1
        i += 1
    if count == 0:
        print("Prime number")
    else:
        print("Not a prime number")
  • count بيعد القواسم الإضافية، مش الأعداد اللي جرّبناها كلها.
  • i بتزيد سواء لقينا قاسم أو لأ.
  • ده حل تعليمي بسيط، ومش مخصص للأعداد الضخمة.
إجابة سؤال التوقع

لأن كل عدد صحيح بيقبل القسمة على 1، وده مش دليل إنه غير أولي.

خد بالك: 1 مش عدد أولي، و2 أولي رغم إن الحلقة هنا لا تنفّذ أي دورة.

المقارنة مع الملف المرفق

الكود المرفق بيفترض عددين موجبين غير صفر. هنا استخدمنا صيغة إقليدس الأقصر، وتعاملنا مع الصفر والسالب. للزوج 0 و0، الدليل يعلن إن مفيش أكبر قاسم موجب بدل اعتماد اصطلاح برمجي.

# Sheet (4), Q #14
a = abs(int(input("Enter the first integer: ")))
b = abs(int(input("Enter the second integer: ")))
if a == 0 and b == 0:
    print("No greatest positive divisor for 0 and 0.")
else:
    while b != 0:
        remainder = a % b
        a = b
        b = remainder
    print("GCD =", a)
  • and معناها إن الشرطين لازم يتحققوا مع بعض.
  • مفيش داعي لترتيب العددين؛ نفس الحلقة تشتغل بالترتيبين.
  • في آخر دورة، b بتبقى صفر وa بتحتفظ بآخر باقي غير صفر.
إجابة سؤال التوقع

عشان باقي القسمة على صفر غير مسموح، وهيوقف البرنامج برسالة خطأ.

خد بالك: احسب remainder قبل ما تغيّر a أو b، لأنك محتاج القيمتين القديمتين.

المقارنة مع الملف المرفق

اتبعنا الرسم وكود الدكتور في تفسير 0 o’clock كرأس فوق عند 90 درجة. أضفنا رفض نصف القطر غير الموجب. ممكن يظهر -0.00 بسبب التقريب العددي؛ ده قريب جدًا من صفر.

# Sheet (4), Q #15
# PLAN
# WANT: coordinates of five vertices
# HAVE: radius; centre at (0, 0); first point at top
# CONVERT: degrees to radians
# RELATE: x = r*cos(angle), y = r*sin(angle)
# CHECK: x*x + y*y is approximately r*r
import math
radius = float(input("Enter a positive radius: "))
if radius <= 0:
    print("Radius must be positive.")
else:
    for i in range(5):
        # 1. Convert the next angle to radians.
        angle = math.radians(90 - i * 72)
        # 2. Compute the two coordinates.
        x = radius * math.cos(angle)
        y = radius * math.sin(angle)
        print(f"Point {i+1}: ({x:.2f}, {y:.2f})")
  • math.radians بتحول وحدة الزاوية فقط.
  • cos بيحدد الجزء الأفقي وsin الجزء الرأسي.
  • الحلقة تنفذ 5 مرات، فبتطبع 5 رؤوس.
إجابة سؤال التوقع

لأن sin وcos في math بيستقبلوا راديان، مش درجات. نستخدم math.radians الأول.

خد بالك: لا تخلط i، اللي بيبدأ من صفر، برقم النقطة المعروض i+1.

تدريب: غيّر نصف القطر من 10 إلى 20. إيه اللي يحصل للإحداثيات مع ثبات الزوايا؟
