Chapter 1

Where your work lives

After this chapter you can put every file for this course in one place, name it so you can find it in ten seconds, and carry it home and back.

1.1One folder for the term, one per sheet, one file per question

Before any Python, decide where the files go. It sounds like housekeeping. It is not: a program you cannot find is a program you cannot run, fix, or show at the exam, and a file saved in the wrong folder looks exactly like a program that "does not work". So the shape is fixed now, for the whole term:

1.2Names that sort, and that Python accepts

A file name has three parts, and each one does a job:

  1. 1q05 - the question number, with two digits. Computers sort names letter by letter, so q1, q10, q11, q2 is the order you get with one digit, and q01 ... q09, q10 with two.
  2. 2_minutes - one word saying what it does, joined with an underscore. No spaces: Python runs a file called sheet 1 q5.py today, but spaces break things later, when one file uses another.
  3. 3.py - the extension. It is what tells PyCharm and Windows that this is Python. .txt is a text file, and PyCharm will not offer to run it.
Key idea

If you cannot find a file in ten seconds, it is in the wrong place. Fix it now, while there are three files, not in week 8 when there are forty.

1.3Taking it home, and bringing it back

Assume the lab PC forgets everything by next week: other groups use it, and lab PCs get reset. Before you leave, close PyCharm and copy the whole ECE122 folder from the Desktop to your flash drive, or zip it and send it to yourself. Copy the folder, not single .py files, so the shape comes with it.

Next time, in the lab or at home, open PyCharm and choose Open, then the ECE122 folder. Do not make a new project each week. At home you need Python from python.org and PyCharm from jetbrains.com, both free.

PyCharm shows a great many buttons. For this whole sheet you need four parts of the window. Everything else can wait until the course needs it, and not knowing what to ignore is most of what makes PyCharm feel hard on day one.

Open PyCharm from the desktop. If the first window asks about a trial, an account or signing in, choose the free option and skip signing in: everything this course uses is in the free part. Then New Project (or ☰ menu → File → New Project if a project is already open).

Why not the default, "Project venv"? · optional

A "venv" is a private, empty copy of Python for one project. It is a good habit for professional work. The lab PCs have extra libraries (numpy, pandas, matplotlib) installed into the main Python, and a fresh venv cannot see them, and cannot download them either, because the lab is offline. Selecting the existing Python avoids a surprise later in the term. For sheet 1 either works.

Chapter 3

print() shows, input() asks - and gives text

After this chapter you can predict exactly what print puts on the screen, and say what is inside a variable that came from input().

3.1print puts one space between items

The lecture's Example 4 prints a label and a number on each line, separated by a comma. Here it is, and what it really prints:

run · spaces shown as ·
x1·+·x2·=··25
x1·-·x2·=··5
x1·*·x2·=·150
x1·/·x2·=··1.5
x1**2·=··225

Look at the green dots. Four lines have two spaces before the number, and the third has one. The text 'x1 + x2 = ' already ends with a space, and print adds another between the two items. Line 6's text ends with =, so it gets just the one from print. Neither is wrong; it is worth knowing where every space comes from, because the sheet's answers are full of them.

Two more things this example shows. # starts a comment: Python ignores the rest of that line, and people read it. And x1 / x2 prints 1.5, a decimal, which is chapter 5.

3.2input() always gives text

input('Enter a number: ') shows its message in the Run window, waits for you to type and press Enter, and hands the program what you typed, as text. Always text, even when you typed digits. Python calls text a string, and shows it in quotes: '21'.

Key idea

Whatever the user types arrives as text. Before you do arithmetic with it, turn it into a number. Chapter 4 is how.

بالمصري

input() بترجعلك كلام مش رقم، حتى لو كتبت أرقام. "21" في 2 تبقى "2121" مش 42.

What could fool you
  • It looks like a number. print(x) shows 21 either way; the quotes only appear when Python shows you what is inside. The difference shows up the moment you calculate.
  • No space at the end of the prompt. input('Enter a number:') puts your answer right against the colon: Enter a number:21. End the prompt with a space.
  • "21" + "1" is "211", not 22. Adding two pieces of text joins them.
  • Capitals. Name and name are two different variables. The lecture's Example 3 uses capitals; whatever you choose, use it the same way every time.

Check yourself

x = input('Enter a number: '), and the user types 21. What does print(x * 2) show?

Chapter 4

Turning text into a number

After this chapter you can choose between int(), float() and eval(), read two numbers from one line, and explain why the sheet's answers use eval(input(...)).

4.1Three functions, three sets of rules

Each takes text and tries to make a number of it. They differ in what text they accept:

This is why sheet 1's first program has a trap in it. Written with int(input(...)), it works for 43 and stops for 36.6, with a red ValueError. int(36.6) on a number would quietly give 36, but here int receives the text '36.6', and text with a point in it is not a whole number.

4.2Try any text

4.3Two numbers from one line

Q8 asks for a speed and an acceleration. The sheet's answer reads both at once:

run
Enter speed and acceleration: 60,3.5
The minimum runway length for this airplane is 514.29 meters

eval reads 60,3.5 as two values, and v, a = puts the first in v and the second in a. The count must match: type one number and Python stops with TypeError: cannot unpack non-iterable int object; type three and it says ValueError: too many values to unpack (expected 2, got 3). Type them with a space instead of a comma and it is SyntaxError: invalid syntax. So say it in the prompt: separate them with a comma.

Is eval() a good idea? · optional

eval() runs whatever is typed as Python. In your own programs, with you typing the answers, that is fine, and it is what makes 150,3.5 arrive as two numbers. Programs that read text from strangers - a web form, a file from the internet - never use it, because a stranger could type Python that does damage. There, float(input(...)) reads one number safely. You will meet the safe way to read several numbers later in the course.

بالمصري

int() بتقبل رقم صحيح بس، وfloat() أي رقم واحد، وeval() بتقرا اللي كتبته كأنه بايثون، فتقدر تكتب رقمين بينهم فاصلة.

What could fool you
  • One eval missing out of three. Q6 reads three numbers. Forget eval on T_final only, and T_final - T_initial stops with TypeError: unsupported operand type(s) for -: 'str' and 'float' - text minus a number.
  • A space instead of a comma between two numbers. SyntaxError: invalid syntax.
  • A leading zero. eval('036') is a SyntaxError (Python refuses whole numbers written with a leading zero), while int('036') is 36.
  • 1e9 is a float. eval('1e9') is 1000000000.0, with the .0. Q5's answer prints it with format, so you never see the difference.

5.2// counts whole blocks, % keeps the leftover

Q5 turns a number of minutes into years and days. That needs whole hours, whole days and whole years, plus the days that do not make a full year. // and % are exactly those two questions:

5.3Powers first, and brackets around a fraction

Python does ** before * / // %, and those before + -. Equal ones go left to right. So Q1's 9 / 5 * C + 32 is (9 ÷ 5) × C, then + 32, as the formula means. But a square root written as a fraction needs brackets:

run
print(9 ** 1/2, 9 ** (1/2))
4.5 3.0

Without brackets Python does 9 ** 1 first, then divides by 2. That is why Q10's answer writes every root as ** (1 / 2), and why ** 0.5 is the safer habit.

بالمصري

// بتعدّ كام مرة كاملة، و% بتديك الباقي. و/ العادية دايمًا بتطلع رقم عشري.

What could fool you
  • ^ for a power. 2 ^ 3 prints 1, with no error. Use **.
  • % is not "percent". 50 % 10 is 0, the remainder.
  • A fraction in a power without brackets. x ** 1/2 is half of x.
  • Expecting / to give a whole number. 10 / 2 is 5.0. If you need whole units, you need //.

Chapter 6

Showing a number: format()

After this chapter you can read any format code on the sheet, predict the spaces in front of a number, and choose how many digits to show.

6.1Why 36.6 °C comes out as 97.88000000000001

Computers store decimals in binary, and most decimals, like 0.1, have no exact binary form, the way 1/3 has no exact decimal form. The tiny error shows up when Python prints the full value:

run
print(9 / 5 * 36.6 + 32)
97.88000000000001
print(0.1 + 0.2)
0.30000000000000004

Nothing is broken, and the error is far too small to matter for an engineer. But nobody wants to read it. format() chooses how the number is shown; it never changes the number itself.

6.2Reading a format code

6.3The spaces in the sheet's answers are not your mistake

The answers the lecturer supplied use widths, so their output has spaces in front of the numbers. Here is Q3's, run with 10 feet:

reference answer, Q3 · spaces shown as ·
Enter a value for feet: 10
···10.00·feet·is·····3.05·meters

"8.2f" makes 10.00 (5 characters) 8 wide, so 3 spaces go in front; then print adds its own space between items, which is why there are 5 before 3.05. If your version prints 10.0 feet is 3.05 meters, the numbers are the same; only the layout differs. Widths are for lining numbers up in columns; when you are printing one line, ".2f" reads better.

بالمصري

الرقم الأول في "8.2f" هو العرض الكلي، وبعد النقطة عدد الأرقام العشرية. المسافات اللي قبل الرقم طبيعية ومش غلط منك.

What could fool you
  • format() gives text. format(3.14159, ".2f") + 1 stops with TypeError: can only concatenate str (not "int") to str. Calculate first, format last, inside the print.
  • 2.675 to two digits is 2.67, not 2.68. The stored value is a hair below 2.675 (6.1 again), and format rounds what is really stored.
  • A width too small never cuts a number. The number is shown in full and the width is ignored.
  • "e" writes the power of ten after the e: 1.0e+09 means 1.0 × 109.

Check yourself

What does print('[' + format(3.14159, '8.2f') + ']') show?
